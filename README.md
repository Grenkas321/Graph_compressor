# graph_compressor

Решение задачи об эффективной сериализации/десериализации неориентированного
взвешенного графа. Критерий — размер `graph.bin`, при условии что входной файл
восстанавливается точно (с точностью до порядка строк и перестановки первых двух
идентификаторов в строке).

## Запуск

```
./run -s -i input.tsv -o graph.bin     # сериализация
./run -d -i graph.bin -o output.tsv    # десериализация
```

Сборка:

```
mkdir build && cd build
cmake -DCMAKE_BUILD_TYPE=Release ..
make
```

## Соответствие условиям проверки

| Требование задания | В решении |
| --- | --- |
| Компиляция без сторонних библиотек | Только стандартная библиотека C++17, сборка одним `CMakeLists.txt` |
| Не использовать `gzip`, `boost`, `proto` и т. п. | Арифметический кодер и модели написаны в `src/codec/`, внешних форматов нет |
| Однопоточность | Потоки не создаются, `<thread>` не подключается |
| Время (сериализация + десериализация) ≤ 5 минут | 4.9 с на `large_example.tsv` (2.8 с + 2.1 с), пик памяти 227 МБ |
| `output.tsv` совпадает с `input.tsv` с точностью до перестановок | Проверяется `tools/verify.py` на всём наборе тестов |
| Числа разделены табуляцией, без лишних пробелов | Запись идёт собственным форматтером `TTsvWriter`, строка — ровно `id\tid\tweight\n` |
| `N ≈ 10^6` вершин, файл ≤ 160 МБ | `large_example.tsv` (154.6 МБ, N = 1 234 567, M = 6 172 810) проходит целиком |
| Возможны петли, кратных рёбер нет, изолированных вершин нет | Петля кодируется как ребро `u–u`, тест `loops`; изолированные вершины не предполагаются и не хранятся |
| Идентификаторы из `[0, 2^32 − 1]`, веса из `[0, 2^8 − 1]` | Границы покрыты тестами `single edge` и `star` (`4294967295`, вес `255`) |

## Результаты

| Файл | Исходный размер | `graph.bin` | Коэффициент |
| --- | --- | --- | --- |
| `small_example.tsv` | 1 252 680 | 143 721 | 8.72 |
| `large_example.tsv` | 154 654 622 | 21 792 537 | 7.10 |

Для сравнения, `gzip -9` на `large_example.tsv` даёт 55 662 262 байта — в 2.6 раза
больше.

## Оценка снизу и что из неё следует

Задание обещает три свойства входа: разреженность (`M ≤ 5N`), степенное
распределение степеней и равномерность весов и идентификаторов. Из них сразу
считается, сколько информации в графе есть на самом деле. Для `large_example.tsv`:

| Компонента | Оценка снизу | Получено |
| --- | --- | --- |
| Идентификаторы вершин, `log2 C(2^32, N)` | 2.038 МБ | 2.042 МБ |
| Степени вершин, `N * H(deg)` | 0.559 МБ | 0.563 МБ |
| Структура графа, `sum log2 C(доступные, d)` | 13.040 МБ | 13.013 МБ |
| Веса рёбер, `8 * M` бит | 6.173 МБ | 6.173 МБ |
| **Итого** | **21.810 МБ** | **21.793 МБ** |

Это и определило архитектуру: выигрывать можно только за счёт модели источника,
а не за счёт «более плотной упаковки байтов», поэтому в основе лежит
арифметический кодер с адаптивными контекстными моделями, а не битовые
упаковщики. Идентификаторы и степени упираются в свои пределы с точностью до
0.2 % и 0.8 %, веса несжимаемы по условию — вся работа идёт в структуре.

Строка структуры требует оговорки. `sum log2 C(доступные, d)` — это стоимость
графа, у которого каждый список равновероятно выбран из вершин, ещё способных
принять ребро. Это не нижняя граница задачи, а стоимость модели, не знающей
ничего, кроме степеней. Настоящий граф не таков: вероятность попасть в вершину
растёт с её остаточной степенью, степени распределены по степенному закону, и
на этом можно выиграть 0.53 бита на ребро (измерено взвешенной бернуллиевской
моделью, `412 КБ` на `large_example.tsv`). Поэтому решение эту величину
проходит насквозь, а не приближается к ней снизу.

Обещанные свойства проверены на данных (скрипты в `tools/`), чтобы не строить
модель на предположении: энтропия веса 7.99997 бита из 8, идентификаторы
равномерны, показатель степенного закона около 2.6, корреляция степеней концов
ребра −0.006, число треугольников не превышает ожидаемого для случайного графа.
Дополнительной структуры, которую стоило бы эксплуатировать, в графе нет.

## Формат `graph.bin`

```
"GRC1"                         сигнатура, 4 байта
<арифметически закодированный поток>:
    N                          32 прямых бита
    M                          64 прямых бита
    флаг кодирования весов     1 прямой бит
    идентификаторы вершин      N значений
    степени вершин             N значений
    списки смежности и веса    M пар
```

1. **Идентификаторы.** Вершины нумеруются по возрастанию идентификатора,
   кодируются разности соседних значений. Разности геометрические со средним
   `2^32 / N`, модель целых чисел выдаёт на них почти точно
   `log2(2^32/N) + log2(e)` бита.

2. **Степени.** Кодируется `deg - 1` (изолированных вершин нет по условию).
   Степени нужны не только сами по себе: длина списка смежности вершины не
   хранится вообще, декодер вычисляет её как число ещё не встреченных рёбер
   вершины.

3. **Списки смежности.** Кодируются не в порядке идентификаторов, а в порядке
   убывания степени (при равных степенях — по возрастанию номера). Перестановка
   не передаётся: степени уже в потоке, и декодер строит её сам подсчётом.

   Порядок нужен вот зачем. Модель считает все доступные вершины
   равновероятными, а на деле вероятность попасть в вершину растёт с её
   остаточной степенью. Выразить это рангом нельзя — ранг не знает, на кого
   указывает. Но если отсортировать вершины по степени, вес превращается в
   позицию: вершины, куда ребро попадает часто, собираются в начале, ранги
   становятся малыми, и адаптивная модель выучивает форму сама, без единого
   нового параметра. На `large_example.tsv` это 379 606 байт.

   Каждое ребро хранится один раз — у конца, который в этом порядке идёт
   первым, поэтому список строго возрастает.

   Сосед кодируется не разностью номеров, а рангом среди вершин, которые ещё
   способны принять ребро. Обе стороны ведут счётчик незакодированных рёбер
   каждой вершины (он выводится из степеней, а степени идут в потоке раньше),
   и вершина с нулевым счётчиком целью быть уже не может. Такие вершины
   выбрасываются из отсчёта, и каждое значение становится короче. Разница по
   отрезку порядка процента, но платится она на каждом из 6 172 810 рёбер: на
   `large_example.tsv` в порядке идентификаторов это давало 37 837 байт.

   Множество хранится в `TVertexSet`: кодеру нужен ранг вершины, декодеру —
   вершина по рангу. Обе операции логарифмические, но здесь важна не
   асимптотика, а размер рабочего набора: дерево Фенвика прямо по флагам
   занимает мегабайты и на каждый запрос даёт промахи кэша, поэтому флаги
   хранятся битовой картой, а дерево считает единицы по блокам в 512 бит.
   Дерево ужимается до килобайтов, блок — ровно кэш-линия, и восстановление
   ускоряется на 30 % против прямого дерева.

   Для очередного ранга известны число доступных вершин `reachable` и число
   оставшихся соседей `left`; пара `(reachable / left, left)` образует контекст
   модели. Такой контекст делает распределение внутри контекста
   масштабно-однородным, и адаптивная модель сходится к его энтропии.

4. **Веса.** По условию равномерны, поэтому для них выгоднее прямые 8 бит, чем
   адаптивная модель, которая всегда платит за собственное обучение.
   Сериализатор считает энтропию гистограммы весов и выбирает способ, записывая
   выбор в поток: на равномерных весах экономится 8.7 КБ, на смещённых
   (проверяется тестом `skewed weights`) выигрывает модель. Так решение не
   проигрывает, если закрытый тест окажется не таким равномерным, как обещано.

## Устройство кода

```
src/common/     типы, исключения, битовые утилиты
src/io/         буферизованный ввод-вывод байтов
src/codec/      арифметический кодер и адаптивные модели
src/graph/      модель графа, чтение и запись TSV, сериализация
src/app/        разбор командной строки и сценарий работы
tools/          генератор тестов, проверка round trip, запуск тестов
```

Слои зависят только «вниз»: `codec` не знает про графы, `graph` не знает про
командную строку. Файловые дескрипторы и буферы принадлежат объектам
(`TByteOutput`), ошибки сообщаются исключением `TException`, копирование
объектов, владеющих ресурсами, запрещено явно.

Ключевые классы:

* `TRangeEncoder` / `TRangeDecoder` — двоичный арифметический кодер. Состояние
  одной модели — 32 бита: 16 бит оценки вероятности и счётчик наблюдений, по
  которому выбирается скорость адаптации (быстрая у молодой модели, медленная
  у зрелой). Это важно, потому что формат смешивает контексты, встречающиеся
  миллионы раз, с контекстами, встречающимися единицы раз.
* `TIntegerModel` — модель неотрицательных целых. Число раскладывается на
  экспоненту и мантиссу, экспонента кодируется двоичным деревом (её
  распределение выучивается целиком), старшие биты мантиссы — вторым деревом,
  младшие пишутся напрямую. На геометрических распределениях любого масштаба
  схема отстаёт от энтропии источника на тысячные доли бита.
* `TGraph` — компактное представление графа (CSR верхнего треугольника).
* `TVertexSet` — множество вершин, ещё способных принять ребро: битовая карта
  плюс дерево Фенвика по блокам. Ранг вершины и вершина по рангу за логарифм,
  и рабочий набор помещается в кэш.
* `TGraphSerializer` / `TGraphDeserializer` — формат `graph.bin`.

## Тесты

```
./tools/run_tests.sh
```

Каждый тест — полный цикл `-s` + `-d`, результат сравнивается с исходным файлом
ровно тем же критерием, что и при проверке задания: множества строк должны
совпадать с точностью до порядка строк и перестановки первых двух
идентификаторов (`tools/verify.py`). Набор:

| Тест | Что проверяет |
| --- | --- |
| `single edge` | Минимальный граф, идентификатор `2^32 − 1` |
| `loops` | Петли, вес `255`, вес `0` |
| `star` | Вершина большой степени, разреженные идентификаторы |
| `random ... seed 1..3` | Степенное распределение степеней, равномерные веса |
| `constant weights` | Вырожденная гистограмма весов |
| `skewed weights` | Неравномерные веса — срабатывает выбор модели весов |
| `200000 vertices` | Масштаб, близкий к боевому |

Входные графы для последних четырёх пунктов строит `tools/generate.py`
(степенной закон, заданная доля петель, режим распределения весов).
